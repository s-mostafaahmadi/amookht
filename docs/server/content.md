# تولید محتوا و ضد-تکرار

بزرگ‌ترین ریسک یک پلتفرم تمرین زبان، **تکرار شدن سؤال‌ها** است. آموخت سه لایهٔ جدا برای این مشکل دارد:
انتخاب محتوا (`picks`)، مخزن محتوا (`content_bank`) و پک‌های ثبت‌شده (`owner_session_packs`).

## ۱. موتور برنامه — `testdaf-method.js` (`window.TDM`)

هر روز یک سند روز (`days[YYYY-MM-DD]`) دارد:

```js
{ date, wd, week, mode: 'normal'|'exam'|'eval', level, picks: {...}, redemittel: [...], work: {}, results: {} }
```

`picks` یعنی «امروز چه محتوایی انتخاب شد»:

| کلید | معنی |
| --- | --- |
| `hoeren` | شناسهٔ یک بستهٔ شنیداری (فایل صوتی + سؤالات + ترنسکریپت) |
| `lesen` | شناسهٔ یک متن خواندنی + واژگان |
| `schreiben` | `{ kind: 'grafik'|'argumentation', id }` |
| `sprechen` | آرایهٔ شناسهٔ تسک‌های گفتاری |
| `spBase` | شناسهٔ پایهٔ Sprechen |

### جلوگیری از تکرار در سطح انتخاب

1. **مجموعهٔ مصرف‌شده**: پیش از انتخاب، شناسه‌های استفاده‌شدهٔ همهٔ روزهای گذشته جمع می‌شوند
   (`pickIds(day.picks)`)، پس یک متن/فایل صوتی تا اتمام استخر تکرار نمی‌شود.
2. **تلاش مجدد جهت‌دار**: در «تمرین تازه» تا ۱۲ بار انتخاب دوباره انجام می‌شود تا ترکیب کاملاً تازه به دست آید
   (`for (attempt < 12) { delete day.picks; buildActivities(); if (!overlap) break; }`).
3. **پاک‌سازی وضعیت روز**: با تمرین تازه، `day.work` و `day.results` صفر می‌شوند تا پاسخ‌های قبلی به تمرین
   جدید نچسبند.
4. **استخر سطح‌بندی‌شده**: محتوا بر اساس سطح (A1…C1) و فاز یادگیری (Phase 1–3) فیلتر می‌شود؛ بنابراین
   «تازه بودن» به معنی «نامناسب بودن» نیست.
5. **سقف روزانهٔ تمرین تازه**: ۳ بار در روز برای حساب عادی (`DAILY_RENEW_LIMIT`) و بدون سقف برای مالک/مدیر.
   این هم بار سرور را کنترل می‌کند و هم از «زر زدن برای دیدن سؤال تازه» جلوگیری می‌کند.

### Redemittel و واژگان

- `redemittel` هر روز از تسک‌های Schreiben/Sprechen انتخاب و در `redemittelSeen` ثبت می‌شود تا عبارت تکراری
  در چند روز پشت‌سرهم نیاید.
- واژگان از SRS می‌آیند: کلمه‌ای که مرور آن رسیده دوباره ظاهر می‌شود، اما کلمهٔ تازه از استخر
  استفاده‌نشده برداشته می‌شود.

## ۲. مخزن محتوا — `routes/content_bank.py`

محتوای تولیدشده (با AI یا دستی) در جدول `content_bank` ذخیره می‌شود:

- کلید یکتا: `(topic_key, skill_key)`؛ بنابراین تولید دوبارهٔ یک موضوع/مهارت، رکورد تازه نمی‌سازد
  (upsert با `ON CONFLICT`).
- `skill_key` محدود به `wortschatz, grammatik, lesen, hoeren, schreiben, sprechen`.
- `visibility`: `private` (فقط سازنده) یا `global` (همهٔ کاربران واجد شرایط).
- دسترسی: `require_admin` برای تغییر سراسری، `require_premium` برای خواندن محتوای ویژه.
- نتیجه: یک متن خوب که یک بار ساخته شد، برای همه قابل استفاده است و دوباره هزینهٔ AI نمی‌دهد.

## ۳. پک‌های کامل اجرا — `owner_session_packs` (۴.۱.۰)

هر بار که تمرین‌ها عوض می‌شوند (دکمهٔ «ثبت نتیجه و تمرین تازه» یا پایان روز)، یک **اسنپ‌شات کامل** ثبت می‌شود:

```
payload = {
  schema: 1, kind: 'method'|'plan', reason, source_date, created_at,
  user, plan,                              # برنامهٔ روز با فعالیت‌ها و زمان‌ها
  tdm: { mode, level, picks, redemittel }, # انتخاب‌های موتور (کلید بازسازی)
  day_file: { modules: [...] },            # شش ماژول: عنوان، سؤال، پاسخ، ترنسکریپت، صوت
  audio: [{ module, title, src }],
  resources
}
```

- فرمت «معین»: دقیقاً همان `TDM.dayFileSnapshot(date)` که فایل روز مالک را می‌سازد — یک قرارداد، دو مصرف.
- سقف: ۴ مگابایت برای هر پک، ۳۰۰ پک نگهداری؛ قدیمی‌ترها پاک می‌شوند.
- بارگذاری: `S.plan` با تاریخ **امروز** بازنویسی می‌شود و `picks` در روز امروز تزریق می‌شود؛ سپس
  `work/results` خالی می‌شود تا تمرین با محتوای قدیمی ولی از صفر اجرا شود.
- چرا مفید است: بازسازی یک روز خوب برای مرور، تست رگرسیون محتوا، و راهی برای «همان تمرین دیروز را دوباره بده».

## ۴. صدا

- فایل‌های شنیداری در `assets/method-audio/` با نام‌گذاری ثابت (`H11.mp3`, …) و در پک به‌صورت مسیر
  مطلق (`/assets/method-audio/H11.mp3`) ثبت می‌شوند تا از هر کلاینتی قابل پخش باشند.
- ترنسکریپت همیشه همراه فایل صوتی ذخیره می‌شود؛ تمرین «شنیدن انتخابی» و «تحلیل با متن» به آن وابسته‌اند.
- تولید صدا (TTS) یک بار انجام و کش می‌شود؛ کلید یکتای کش = هش متن + صدا.

## ۵. چرخهٔ کامل یک روز

```
ensureToday()  →  rollover (بستن روز قبل + ثبت پک)  →  buildActivities(picks)
     │                                                   │
     ├─ شروع تمرین → stepsFor(module) → تایمر فعال        ├─ questions از استخر سطح
     │                                                   └─ redemittel تازه
     ├─ پایان ماژول → results + errors (SRS)
     └─ «ثبت نتیجه و تمرین تازه» → روز بسته می‌شود → پک ثبت می‌شود → picks تازه (بدون تکرار)
```

## ۶. قواعد کیفیت محتوا

| قاعده | پیاده‌سازی |
| --- | --- |
| هر سؤال باید «شاهد» در متن داشته باشد | فیلد `evidence` در سؤال؛ در فایل روز نمایش داده می‌شود |
| هر سؤال توضیح فارسی دارد | `explain_fa` |
| تعداد سؤال متناسب با زمان فعالیت | `questionTarget` بر اساس دقیقهٔ هر ماژول |
| سطح زبانی هر آیتم صریح است | `level` روی بستهٔ محتوا و فیلتر در انتخاب |
| محتوای تکراری در چند روز پشت‌سرهم ممنوع | مجموعهٔ `used` + retry ۱۲ باره |
| پاسخ‌های اشتباه به مرور برمی‌گردند | SRS چهارسطحی (`SRS_STEPS = [1,3,7,14,30]`) با ease factor و lapses |
