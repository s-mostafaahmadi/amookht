# هوش مصنوعی در آموخت

هوش مصنوعی در آموخت «چسب» محصول نیست، بلکه چهار کار مشخص دارد: **تصحیح نوشتار، تحلیل گفتار و تمرین مکالمه،
تولید محتوای تمرین و دستیار مربی**. همهٔ این‌ها پشت دو لایهٔ کنترلی (`ai_registry` و `ai_guard`) هستند تا
هزینه، تأخیر و خرابی مهار شود.

## ۱. رجیستری ارائه‌دهنده‌ها — `app/api/ai_registry.py`

یک فهرست واحد که **مالک** از پنل مدیریت AI نگه می‌دارد؛ ذخیره در `backend/data/ai_providers.json` (۰۶۴۰).

قابلیت‌ها:

- **چند ارائه‌دهنده هم‌زمان**: Groq، NVIDIA، DeepSeek، هر endpoint سازگار با OpenAI، و سرورهای محلی
  (Ollama / LM Studio / llama.cpp).
- **کلیدها رمزنگاری‌شده**: `Fernet` با کلیدی که از `SECRET_KEY` مشتق می‌شود؛ API هرگز کلید خام برنمی‌گرداند.
- **حالت کلید**: ارائه‌دهنده‌های داخلی در حالت `legacy` شروع می‌کنند (کلید از `API.txt` / `AI_KEYS_FILE` / `.env` /
  `backend/.nvidia_keys`)؛ با افزودن یا حذف کلید به حالت `managed` می‌روند. فایل‌های قدیمی هرگز بازنویسی نمی‌شوند.
- **مسیر هر قابلیت جدا**: `route(feature)` برای `tutor`, `method`, `grammar`, `writing`, `speaking` جداگانه
  ترتیب ارائه‌دهنده و کلید می‌دهد.
- **سازگاری عقب‌رو**: تا وقتی مسیر مؤثر یک قابلیت همان مسیر تاریخی (Groq → NVIDIA) است، `custom_plan()`
  مقدار `None` می‌دهد و **کد قدیمی و آزمودهٔ همان مصرف‌کننده اجرا می‌شود**. هر مسیر دیگری از `complete()` می‌رود.
  یعنی تغییر تنظیمات AI هرگز رفتار پیش‌فرض را عوض نمی‌کند.
- **محافظت SSRF**: URL هر ارائه‌دهنده اعتبارسنجی می‌شود؛ آدرس‌های metadata ابری (169.254.169.254)،
  link-local، multicast و reserved همیشه رد می‌شوند؛ host خصوصی/loopback فقط با پرچم صریح `allow_local`.
- **چرخش کلید و fail-over**: کلیدهای rate-limited علامت می‌خورند و نوبت کلید بعدی می‌شود؛ اگر همه تمام شدند
  ارائه‌دهنده به‌عنوان down علامت می‌خورد.

## ۲. نگهبان هوش مصنوعی — `app/api/ai_guard.py`

هدف: هیچ درخواست کاربری بیش از بودجه منتظر نماند و هیچ خرابی‌ای کل سیستم را کند نکند.

| مکانیزم | جزئیات |
| --- | --- |
| **Deadline** | هر درخواست بودجهٔ کل زمان دارد؛ هر تلاش ارائه‌دهنده فقط از باقی‌ماندهٔ بودجه می‌خورد |
| **Circuit breaker** | پس از شکست قطعی (همهٔ کلیدها ۴۲۹/۴۰۱ یا دو درخواست پشت‌سرهم اتمام بودجه) ارائه‌دهنده ۹۰ ثانیه down می‌شود؛ پاسخ فوری `503 ai_unavailable` با `retry_after` |
| **حالت مشترک** | وضعیت در Redis است تا هر دو worker یک دید داشته باشند؛ اگر Redis قطع شود fallback درون‌پروسه‌ای |
| **پنجرهٔ خطا** | خطاهای پشت‌سرهم در پنجرهٔ ۵ دقیقه شمرده می‌شوند (`FAILS_TO_TRIP = 2`) |
| **ریست** | ریست از پنل مدیریت، وضعیت هر دو worker را پاک می‌کند |

## ۳. سهمیه و محدودیت مصرف

متغیرهای محیطی مربوطه:

```
AI_WRITING_RATE_LIMIT / AI_WRITING_RATE_WINDOW_SECONDS
AI_WRITING_DAILY_QUOTA / AI_WRITING_DAILY_WINDOW_SECONDS
AI_WRITING_LEASE_SECONDS       # قفل ضد-تکرار برای یک درخواست یکسان
AI_WRITING_TIMEOUT_SECONDS
AI_WRITING_MAX_INPUT_CHARS     # سقف ورودی (ضد سوءاستفادهٔ حجمی)
AI_TLOS_ENABLED / _TIMEOUT_SECONDS / _MAX_TOKENS
```

- **lease**: اگر کاربر دکمهٔ «تصحیح» را دوباره بزند، درخواست دوم به‌جای هزینهٔ دوباره همان نتیجهٔ در جریان را می‌گیرد.
- **سقف روزانه**: پس از اتمام، پاسخ روشن «سهمیهٔ امروز تمام شد» (نه خطای مبهم).
- **سقف طول ورودی**: متن بلندتر از حد، قبل از ارسال به مدل رد می‌شود.

## ۴. قابلیت‌های AI و مسیرشان

| قابلیت | روتر | چه می‌کند |
| --- | --- | --- |
| تصحیح نوشتار | `routes/writing.py` | نمرهٔ کلی/گرامر/واژگان/انسجام + فهرست خطاها با اصلاح و توضیح فارسی؛ خطاها به دفتر اشتباهات و SRS می‌روند |
| مربی گفتگو | `routes/language_coach.py` | مکالمهٔ سطح‌بندی‌شده با تصحیح درجا؛ bridge آن در فرانت `coach-bridge.js` است |
| گفتار | `routes/speaking.py` + `infrastructure/ai/stt` | `faster-whisper` محلی برای رونویسی ضبط‌ها، سپس ارزیابی تلفظ/روانی/ساختار |
| تولید محتوا | `routes/owner_agent_content.py`, `content_bank.py` | ساخت تمرین تازه با LLM و ذخیره در مخزن |
| ربات گرامر | `routes/grammar_drill.py` | تمرین گرامر تولیدی بر اساس ضعف‌های همان کاربر |
| تحلیل جمله | `routes/sentence_parts.py` | نقش اجزای جمله (فاعل، فعل، مفعول …) برای رنگ‌بندی فرانت |
| دستیار مالک | `routes/owner_ai_chat.py`, `owner_agent_llm.py`, `owner_agent_tools.py` | چت مدیریتی با ابزار (خواندن آمار، ساخت محتوا، ساخت پک) |
| استاد راهنما (Tutor) | `tools/tutor.js` + `/coach/api` | پنل شناور کمک درسی روی هر تمرین |

## ۵. STT/TTS

- **STT**: `faster-whisper` روی CPU/GPU سرور (`WHISPER_MODEL`, `WHISPER_DEVICE`, `WHISPER_COMPUTE_TYPE`).
  دلیل انتخاب محلی: حریم خصوصی صدای کاربر و هزینهٔ صفر به‌ازای هر دقیقه.
- **TTS**: تولید صدای تمرین‌های شنیداری و پخش تلفظ واژه‌ها؛ خروجی در `assets/method-audio/` کش می‌شود
  تا یک فایل صوتی دو بار تولید نشود.
- محدودیت آپلود: `MAX_UPLOAD_SIZE_MB`؛ نوع فایل و مدت ضبط هم در روتر بررسی می‌شود.

## ۶. تلگرام به‌عنوان کانال

`telegram_service.py` (۴۸KB) + `routes/telegram_link.py` + `routes/owner_ai_chat.py`:

- اتصال امن حساب به تلگرام با توکن یک‌بارمصرف و وب‌هوک با `TELEGRAM_WEBHOOK_SECRET`.
- ارسال گزارش روزانه، یادآور مرور SRS و (برای مالک) تأیید محتوای تولیدشده.
- هیچ پیام تلگرامی بدون تطبیق `chat_id` با حساب تأییدشده پردازش نمی‌شود.

## ۷. گاردریل‌های محتوای AI

1. پاسخ مدل همیشه **JSON با schema مشخص** خواسته می‌شود؛ پاسخ نامعتبر دور ریخته می‌شود (بدون crash).
2. متن تولیدی قبل از نمایش از فیلتر تکراری‌بودن می‌گذرد (نگاه کنید به `content.md`).
3. هیچ کلید API در پاسخ، لاگ یا فرانت ظاهر نمی‌شود؛ فقط نام ارائه‌دهنده و وضعیت.
4. خطای ارائه‌دهنده به زبان کاربر ترجمه می‌شود («سرویس هوش مصنوعی موقتاً در دسترس نیست؛ N ثانیه دیگر»).
5. برای هر قابلیت، مسیر fallback تعریف شده است: اگر مدل نوشتاری جواب نداد، تصحیح قاعده‌محور (rule-based)
   نمرهٔ تقریبی می‌دهد و متن کاربر از دست نمی‌رود.
